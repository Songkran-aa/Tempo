**Tempo** คือระบบทำงานร่วมกันสำหรับทีมการตลาด รวมโปรเจกต์เปิดตัวสินค้า งาน แคมเปญ ฐานข้อมูลครีเอเตอร์/อินฟลูเอนเซอร์ งบประมาณ และคลังสินค้าไว้ในที่เดียว ใช้ได้กับทุกธุรกิจ ไม่ว่าจะเป็นบิวตี้ อาหาร ไอที แฟชั่น ท่องเที่ยว หรือสายไหนก็ตั้งเองได้ ใช้พร้อมกันทั้งทีม รองรับไทย/อังกฤษ เปิดบนมือถือได้และติดตั้งเป็นแอป (PWA)

> **English summary** — Tempo is a self-hosted workspace for marketing teams: product-launch projects (brief, milestones, readiness checklist), tasks (list & board), campaigns, a creator/influencer database with a 9-stage collaboration pipeline, budget requests with approvals, inventory, partners & contracts, a team calendar with `.ics` feeds, comments with @mentions, and notifications. Thai/English UI, mobile-friendly PWA. Node.js + Fastify + PostgreSQL, no build step. MIT licensed.

## สายครีเอเตอร์ (Niches) — ปรับให้เข้ากับธุรกิจของคุณ

Tempo ไม่ผูกกับอุตสาหกรรมใด พื้นที่ทำงานใหม่**เริ่มจากว่าง** แล้วทีมกำหนด "สาย" ของครีเอเตอร์เอง เช่น 💄 บิวตี้, 🍜 อาหาร, 💻 ไอที, ✈️ ท่องเที่ยว, 👶 แม่และเด็ก

- ครีเอเตอร์หนึ่งคนอยู่ได้หลายสาย (สายแรกคือสายหลัก ใช้เป็นไอคอนและชีตตอนส่งออก)
- แต่ละสายมี **ช่องข้อมูลเฉพาะ** ของตัวเองได้ (เช่น บิวตี้: สภาพผิว, อาหาร: เมนูถนัด)
- เปลี่ยนชื่อสายได้โดยไม่กระทบข้อมูลเดิม (รหัสสายไม่เปลี่ยน)
- นำเข้าไฟล์ที่มีสายใหม่ → ระบบเพิ่มสายนั้นให้อัตโนมัติ
- รายงานงบแยกตามสาย (ครีเอเตอร์ที่อยู่สองสายนับในทั้งสองสาย)

## เทคโนโลยีที่ใช้

| ส่วน | ใช้อะไร |
|---|---|
| Backend | Node.js 20.12+, [Fastify 5](https://fastify.dev) (ES modules) |
| ฐานข้อมูล | PostgreSQL 16 (production) · [PGlite](https://pglite.dev) แบบฝังตัวสำหรับพัฒนา/เทสต์ — ไม่ต้องติดตั้ง Postgres |
| Frontend | JavaScript ล้วน (ES modules) ไม่มี framework ไม่ต้อง build · PWA + service worker |
| ไฟล์ | ExcelJS + JSZip (นำเข้า/ส่งออก .xlsx), CSV parser ของตัวเอง |
| อีเมล | Nodemailer (ตัวเลือก) |
| Deploy | Docker Compose + Caddy (HTTPS อัตโนมัติ, load balance) |

## เริ่มใช้งานบนเครื่อง

ต้องมี Node.js 20.12 ขึ้นไป

```bash
git clone <repo-url> tempo && cd tempo
npm install
npm run dev        # http://localhost:3000
```

เปิดเว็บแล้วสมัครบัญชีแรกได้เลย — เมื่อไม่ได้ตั้ง `DATABASE_URL` ระบบใช้ PostgreSQL แบบฝังตัว (PGlite) เก็บไว้ที่ `./data` (สำหรับพัฒนาเท่านั้น) ระบบไม่มีบัญชีหรือข้อมูลตัวอย่างติดมา

## ตั้งค่า (Environment variables)

คัดลอก `.env.example` เป็น `.env` แล้วแก้ค่า

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `DOMAIN` | — | โดเมนของเว็บ (Caddy ออกใบรับรอง HTTPS ให้) |
| `POSTGRES_PASSWORD` | — (ต้องตั้ง) | รหัสผ่านฐานข้อมูลใน Docker Compose |
| `POSTGRES_USER` / `POSTGRES_DB` | `tempo` | ชื่อผู้ใช้/ฐานข้อมูล |
| `DATABASE_URL` | ว่าง = PGlite | ต่อ Postgres ภายนอก (เช่น RDS, Cloud SQL, Supabase, Neon) |
| `DB_SSL` | `0` | ตั้ง `1` ถ้า Postgres ต้องใช้ SSL |
| `DB_POOL_MAX` | `20` | connection ต่อ instance |
| `APP_REPLICAS` | `2` | จำนวน instance ของแอป |
| `PORT` | `3000` | พอร์ตของแอป |
| `ALLOW_SIGNUP` | เปิด (`.env.example` ตั้ง `0`) | `0` = สมัครได้เฉพาะอีเมลที่ได้รับเชิญ / บัญชีที่แอดมินสร้าง |
| `SESSION_DAYS` | `30` | อายุเซสชัน (วัน) |
| `UPLOAD_MAX_MB` | `15` | ขนาดไฟล์นำเข้าสูงสุด |
| `COOKIE_SECURE` | อัตโนมัติ | บังคับ cookie แบบ Secure (`1`) หรือปิด (`0`) |
| `SMTP_URL` / `MAIL_FROM` / `APP_URL` | ว่าง | ส่งอีเมลแจ้งเตือน (ไม่ตั้ง = แจ้งเตือนในแอปอย่างเดียว) |
| `COMPOSE_FILE` / `APP_PORT` | — | รันหลัง reverse proxy ของตัวเองแทน Caddy (ดู `deploy/docker-compose.port.yml`) |

## ขึ้นเซิร์ฟเวอร์จริง

ดูขั้นตอนทั้งหมดใน **[DEPLOY.md](DEPLOY.md)** — สรุป:

```bash
sudo bash deploy/install-ubuntu.sh                                                       # Docker + ไฟร์วอลล์ + .env + HTTPS + สำรองรายวัน
docker compose exec app node server/scripts/create-user.js <อีเมล> "<ชื่อ>" "<นามสกุล>"      # สร้างบัญชีแรก
docker compose exec app node server/scripts/import-workspace.js restore/<ไฟล์>.xlsx <อีเมล>  # นำเข้าข้อมูล (ถ้ามี)
```

ได้ PostgreSQL 16 + แอป 2 instance (ปรับ `APP_REPLICAS`) + Caddy ทำ HTTPS อัตโนมัติ (Let's Encrypt) + สำรองฐานข้อมูลทุกวัน (`deploy/backup.sh`)

## นำเข้า / ส่งออกข้อมูล

### ไฟล์ Tempo (.xlsx) — ย้ายทั้งพื้นที่ทำงาน

`ตั้งค่า → ข้อมูล → ส่งออกทั้งพื้นที่ทำงาน / นำเข้าไฟล์ Tempo`

| ชีต | เนื้อหา |
|---|---|
| อ่านก่อน | กติกาของไฟล์ |
| Projects · Milestones · Readiness · Brief | โปรเจกต์ + หมุดหมาย + เช็กลิสต์ความพร้อม + Brief (อ้างโปรเจกต์ด้วยรหัสหรือชื่อ) |
| Tasks · Campaigns | งาน และแคมเปญ |
| Influencers | ครีเอเตอร์ (จับคู่ด้วย ID) |
| Collaborations | งานครีเอเตอร์ (อ้างครีเอเตอร์ด้วย ID และแคมเปญด้วยรหัส) |
| Lists | ค่าที่ใช้ได้ของสถานะ/ตัวเลือก (มี dropdown ในชีตอื่น) — ใช้รหัสหรือชื่อไทย/อังกฤษก็ได้ |

- ทุกแถวมี **รหัส** → นำเข้าซ้ำจะ **อัปเดต ไม่สร้างซ้ำ** · ช่องว่างไม่ลบข้อมูลเดิม · คนอ้างด้วยอีเมล
- `npm run verify -- <file.xlsx>` ตรวจไฟล์ได้ (นำเข้า → ส่งออก → เทียบ) โดยไม่แตะข้อมูลจริง

### ไฟล์ครีเอเตอร์ (.xlsx)

หัวคอลัมน์ที่รู้จัก (ไทยหรืออังกฤษ, ไม่ต้องครบทุกช่อง — ขอแค่มี `Account Name`):
`ID`, `Account Name`, `สาย / ประเภท`, `Tier`, `Follower …` (แยกแพลตฟอร์ม), `Link TikTok / IG / Facebook / X / Lemon8 / YouTube`, `LINE ID`, `เบอร์โทร`, `Email`, `ที่อยู่จัดส่ง`, `แบรนด์ที่เคยร่วมงาน`, `หมายเหตุ / เงื่อนไข / เรท`, `⚠ Blacklist` ฯลฯ — ไฟล์ที่ส่งออกจาก Tempo ใช้รูปแบบเดียวกัน นำกลับเข้ามาได้ทันที

### ไฟล์งาน (CSV) และโปรเจกต์ (JSON)

- **CSV งาน** (`งาน → ⋯ → นำเข้า CSV`): คอลัมน์ `ID, โปรเจกต์, แบรนด์, สินค้า, รุ่น / สูตร, ขั้นตอน, งานที่ต้องทำ, ผู้ประสานงาน, เจ้าของงาน, สถานะ, เดดไลน์, งานถัดไป, หมายเหตุ, …` — โปรเจกต์ที่ยังไม่มีจะถูกสร้างพร้อมเทมเพลต
- **JSON โปรเจกต์** (`npm run import:projects`): โปรเจกต์ + Brief + หมุดหมาย + เช็กลิสต์ + งาน — ดูรูปแบบที่ [`server/test/fixtures/sample-bundle.json`](server/test/fixtures/sample-bundle.json)
- รวมหลายไฟล์เป็นไฟล์ Tempo ไฟล์เดียว (ทำในฐานข้อมูลชั่วคราว ไม่แตะข้อมูลจริง):

```bash
npm run convert -- --bundle projects.json --tracker tracker.csv \
  --influencers creators.xlsx --name "My Workspace" --out Tempo_MyWorkspace.xlsx
```

## สถาปัตยกรรม

```
Browser (PWA, ES modules)  ──HTTPS──▶  Caddy  ──▶  app × N (Fastify, stateless)  ──▶  PostgreSQL 16
        ▲   ตรวจ revision ทุก 15 วิ / เมื่อกลับมาที่แท็บ                    │
        └──────────────── โหลดข้อมูลพื้นที่ทำงาน (bootstrap) ◀──────────────┘
```

- แอปเป็น **stateless** (เซสชันอยู่ใน PostgreSQL) → เพิ่ม instance ได้ทันที Caddy กระจายโหลดให้
- **ซิงก์ข้อมูล** ด้วยเลข revision ต่อพื้นที่ทำงาน — client ถามแค่ตัวเลข (เบามาก) แล้วโหลดใหม่เมื่อมีการเปลี่ยนแปลง
- ฐานข้อมูลครีเอเตอร์ ค้นหา/แบ่งหน้าฝั่งเซิร์ฟเวอร์ มี index ตามผู้ติดตาม/สาย/รหัส
- Migration เป็นไฟล์ SQL/JS เรียงลำดับใน `server/migrations/` รันอัตโนมัติตอนเปิดเซิร์ฟเวอร์
- Rate limit: ทั้งระบบ 600 ครั้ง/นาที/IP, ล็อกอิน/สมัคร 10 ครั้ง/นาที/IP

## ความปลอดภัยและข้อมูลส่วนบุคคล

- scrypt password hashing · cookie httpOnly + SameSite=Lax + Secure (production)
- ป้องกัน CSRF ด้วย header · CSP / HSTS ผ่าน helmet
- ตรวจสิทธิ์ทุก API ตามพื้นที่ทำงาน บทบาท และโปรเจกต์ที่แชร์ · ตรวจข้อมูลทุกฟิลด์ฝั่งเซิร์ฟเวอร์ · ลิงก์รับเฉพาะ http(s)
- ข้อมูลครีเอเตอร์มีข้อมูลส่วนบุคคล (เบอร์โทร ที่อยู่) — `.gitignore` / `.dockerignore` กันไฟล์ `.xlsx`, `data/`, `restore/`, `backups/` และ `.env` ไม่ให้เข้า git หรือ Docker image
- **อย่า commit ข้อมูลจริง** — เทสต์ใช้เฉพาะข้อมูลสมมติใน `server/test/fixtures/`

พบช่องโหว่ด้านความปลอดภัย กรุณาแจ้งผ่าน GitHub Security Advisory ของ repo แทนการเปิด issue สาธารณะ

│  └─ assets/              โลโก้และไอคอนแอป

## การทดสอบ

```bash
npm test             # API tests บน PGlite ในหน่วยความจำ — ไม่ต้องมี Postgres
npm run check        # tests + ตรวจคีย์คำแปลไทย/อังกฤษ
```

เทสต์ครอบคลุม: สมัคร/ล็อกอิน/CSRF, สิทธิ์และการแชร์โปรเจกต์, นำเข้า/ส่งออก .xlsx และ CSV (รันซ้ำไม่สร้างซ้ำ), ไฟล์ Tempo ไป-กลับครบ, สายครีเอเตอร์, ช่องทางติดต่อ, หาและรวมรายการซ้ำ, อนุมัติงบ, คลังสินค้า, แจ้งเตือน

## ร่วมพัฒนา

1. Fork แล้วสร้าง branch ใหม่
2. แก้โค้ด — ข้อความบนหน้าเว็บต้องเพิ่มทั้งไทยและอังกฤษใน `web/js/i18n*.js`
3. เปลี่ยน schema → เพิ่มไฟล์ migration ใหม่ (อย่าแก้ไฟล์เดิมที่ปล่อยไปแล้ว)
4. `npm run check` ต้องผ่าน แล้วเปิด Pull Request
5. ข้อมูลทดสอบต้องเป็นข้อมูลสมมติเท่านั้น (อีเมล `@example.com`)
